# 0009. 設計原則：軽さ・純正優先・速やかな撤去・ツール非依存を守り、予算で見張る

- Status: Accepted
- 日付: 2026-10-22
- 関連: docs/design/2026-10-design-principles.md、docs/adr/0001-record-architecture-decisions.md

## Context（背景）
- sdd-lite は、作者が cc-sdd を使って疲れたところから始まった。フェーズごとに承認があり、トークンを多く使い、文書の量も多かった。
- 原案（2026-09-30 の調査資料。非公開）では、次のものを取り入れた。
  - Anthropic（Claude Code チームと社内の使い方）: 共有の CLAUDE.md を育てる。決まった流れはスキルにする。検証はサブエージェントに任せる。変更のリスクで進め方を 2 段階に分ける（周辺の変更は auto-accept、コアの変更は同期で見る）。
  - AWS・Spotify の ADR の文化: 判断は docs/adr/ に残す。ADR の更新を出荷作業に含める。
  - Google のデザインドキュメント: cc-sdd の requirements・design・tasks を 1 ファイルにまとめる。
  - Shopify: 成果物はツールに依存しない素の Markdown にする。
- 当初の構成は、design・adr・ship の 3 スキルと verifier だった。人間の承認は「設計」と「PR」の 2 回。ADR は大規模の変更のときだけ書く。1 か月後に見直して、純正機能と重なった部分を削る予定だった。
- 大企業が Claude の純正機能だけで SDD を回している完全な公開事例は無い。原案は、各社の文化を組み合わせた提案である。
- 1 か月で ask・init・多言語対応（userConfig）が増えた。guide.md はプラグインで最も大きいファイルになり、判断基準は「迷ったら重い方」に寄った。追加の一つ一つは妥当だった。ただ、思想はリポジトリの外（非公開の調査資料と作者の頭の中）にしか無かった。そのため、追加のたびに照らす物差しも、見直しを実行させる仕組みも無かった。

## Decision（決定）
- 原則 1（軽さ）: 人間の承認は「設計の承認」と「PR」の 2 回までにすること。規模の判断に迷ったら軽い方を選び、必要になったら上げること。
- 原則 2（純正優先）: 純正機能で代替できるものを作らないこと。スキル・エージェント・設定・補助ファイルを足すときは、デザインドキュメントに「純正で代替できない理由」と retire-when を書くこと。
- 原則 3（速やかな撤去）: すべてのスキルとエージェントのフロントマターに `retire-when` と `reviewed` を持たせること。月 1 回の見直しで、純正機能の更新と突き合わせること。
- 原則 4（ツール非依存）: 成果物（デザインドキュメント・ADR）は素の Markdown にし、特定のツールの形式に依存させないこと。
- 予算として、次を守ること。
  - スキル（`plugins/sdd/skills/*/SKILL.md`）とエージェント（`plugins/sdd/agents/*.md`）は合わせて 6 以下にすること。
  - `plugins/sdd/skills/ask/guide.md` は 160 行以下にすること。
  - `reviewed` の日付は、実行日から 60 日以内に保つこと。
- 原則と予算を変えるときは、新しい ADR でこの ADR を Superseded にすること。予算の超過を、この ADR を変えずに認めないこと。
- 予算は `.github/scripts/check-principles.sh` で機械的に確かめ、CI（push と PR）で実行すること。

## Consequences（結果）
- 追加のたびに照らす物差しがリポジトリに残る。CLAUDE.md と ADR 0001 の規則（Accepted な ADR に反する実装をしない）が、そのまま原則の見張りになる。
- 予算の違反は CI で止まる。`reviewed` が期限切れになると、関係の無い PR も赤になる。見直しを強制するための意図した挙動であり、見直しの結果は `reviewed` の日付を更新する 1 行の変更で反映する。
- 何かを足すときに「純正で代替できない理由」と retire-when を書く手間が増える。
- この ADR を起票した時点で、次の違反がある。このデザインでは直さず、それぞれ別のデザインドキュメントで直す。
  - userConfig の言語設定（ADR 0006）は、純正の `language` 設定と重なっており、原則 2 に反する。「純正 language 設定への統合」で直し、ADR 0006 を Superseded にする。
  - guide.md の判断基準「迷ったら重い方」は、原則 1 に反する。「軽い方への反転と ship の段階化」で直す。
