# 0011. 規模は軽い方を既定にし、ship を区分で段階化する

- Status: Accepted
- 日付: 2026-10-23
- 関連: docs/design/2026-10-lighter-ship.md、docs/adr/0009-design-principles.md

## Context（背景）
- guide.md の規模の判断は「迷ったら上の区分を選ぶ」「迷ったら B にして ADR を残す」だった。ADR 0009 の原則 1（迷ったら軽い方を選び、必要になったら上げる）に反し、ADR 0009 に既知の違反として記録してあった。
- `/sdd:ship` は、変更の大きさによらず verifier・`/simplify`・`/code-review` をすべて実行していた。文言の修正 1 行でも同じ手間とトークンがかかる。
- 軽い方を既定にすると、ADR や設計が漏れるおそれが増える。ship には、もともと ADR の漏れを確かめる手順がある。
- ship が変更の重さを決める方法として、次のものを比べた。
  - 変更量（`git diff --stat`）: 機械的に決められる。しかし、改行の追加だけの大きな差分を重く、1 行でも全体に効く設定値の変更を軽く判定してしまう。
  - 毎回利用者に聞く: 確実だが、承認が 1 回増え、原則 1（承認は設計と PR の 2 回まで）に反する。
  - 計画のときに作った成果物（デザインドキュメント・ADR）: 人が計画のときに選んだ区分が成果物として残っており、機械的に読める。ただし、成果物が軽すぎた場合を拾えない。
  - 差分の中身: 設定値や公開 API など、少ない行数でも影響が広い変更を拾える。判断に Claude の読みが入る。

## Decision（決定）
- 変更の規模（区分 A / B / C）に迷ったら、軽い方の区分を選ぶこと。計画や実装の途中で設計判断が出てきたら ADR を残して B に、要件の整理が要ると分かったら `/sdd:design` に切り替えて A に上げること。
- `/sdd:ship` は、基本の区分を計画のときの成果物で決めること。`Status: Approved` のデザインドキュメントがあれば A、このブランチで ADR が追加されていれば B、どちらも無ければ C とすること。
- `/sdd:ship` は、空白の違いを無視した差分の中身を読み、設定値・共有の定数・公開 API・スキーマ・依存関係・セキュリティや、プロジェクトの CLAUDE.md に書かれた「重い場所」に触れていれば、区分を 1 段上げること。区分を下げないこと。変更量（行数・ファイル数）を判定に使わないこと。
- `/sdd:ship` は、手順を始める前に区分と理由を 1 行で宣言し、承認を待たずに進めること。利用者は引数か会話での指示で区分を上書きできること。
- `/sdd:ship` は、区分に応じて手順を省くこと。テスト・lint・型チェック、`/code-review`（C は effort low）、ADR の漏れの確認、承認を得てからのコミットと PR の作成は、どの区分でも省かないこと。verifier と `/simplify` は、A では実行し、B では verifier を ADR との整合の確認だけにして `/simplify` を条件付きにし、C では省くこと。
- 区分の判定と手順の正本は ship の SKILL.md に置き、guide には流れと使い分けだけを書くこと。

## Consequences（結果）
- ADR 0009 の既知の違反（「迷ったら重い方」）が解消する。
- 小さな変更の ship が軽くなる。C では verifier と `/simplify` を省き、`/code-review` も low になる。
- 計画のときに軽く選びすぎた変更は、ship の ADR 漏れの確認と、差分の中身による区分の引き上げで拾う。どちらも Claude の読みに頼るので、拾い漏れはありうる。重要な場所はプロジェクトの CLAUDE.md に「重い場所」として書いておく。
- 区分の宣言のあとに承認を待たないので、上書きしたい利用者は宣言を見て止めるか、最初から引数で渡す必要がある。
- `Status: Approved` のデザインドキュメントが、このブランチと関係なく残っていると、A と判定される。ship が完了時に Status を Implemented にするので、通常は残らない。

## 検証方法（任意）
- `grep -n 'When in doubt' plugins/sdd/skills/ask/guide.md` の結果が、軽い方を選ぶ記述の 1 件だけであること。
- `grep -n 'diff --stat' plugins/sdd/skills/ship/SKILL.md` の結果が、変更量を判定に使わないという記述だけであること。
- `bash .github/scripts/check-principles.sh` が 0 で終わること。
