# 0004. スキルの補助ファイルは allowed-tools で確認なしに読めるようにする

- Status: Accepted
- 日付: 2026-10-19
- 関連: docs/design/2026-10-initial-release.md、docs/adr/0003-guide-as-single-source.md

## Context（背景）
- ADR 0003 で、スキルは `${CLAUDE_SKILL_DIR}` の下にある自分のファイル（guide.md やテンプレート）を Read ツールで読むことにした。
- ローカルでの動作確認（デザインドキュメントの T6）で、次のことが分かった。
  - プラグインのディレクトリは作業ディレクトリの外にあるため、既定の設定では、`${CLAUDE_SKILL_DIR}` の下のファイルを Read で読むたびに許可を求められる。`--plugin-dir` で読み込んだ場合も、ローカルのマーケットプレイスから導入した場合も同じだった。
  - 確認を出せない実行（`claude -p`）では、読み取りが拒否され、スキルが手順どおりに進まない。
  - SKILL.md のフロントマターに `allowed-tools: Read(/${CLAUDE_SKILL_DIR}/*)` を書くと、確認なしで読めた。
  - `Read(${CLAUDE_SKILL_DIR}/*)`（先頭の `/` なし）では確認が出た。権限ルールでは絶対パスを `//` で始めるため、`/home/...` に展開される `${CLAUDE_SKILL_DIR}` の前に `/` を 1 つ足す必要がある。

## Decision（決定）
- 自分のディレクトリにあるファイルを読むスキル（`ask`・`adr`・`design`・`init`）は、フロントマターに `allowed-tools: Read(/${CLAUDE_SKILL_DIR}/*)` を書くこと。
- 許可はスキル自身のディレクトリ直下の Read だけにすること。Bash などほかのツールや、ほかのパスを `allowed-tools` で許可しないこと。
- 自分のディレクトリのファイルを読まないスキル（`ship`）とエージェントには書かないこと。

## Consequences（結果）
- 利用者が許可の設定をしなくても、スキルが guide.md やテンプレートを読めるようになる。
- 許可の範囲はスキル自身のファイルの読み取りだけで、作業ディレクトリの外の任意のファイルを読ませることにはならない。
- スキルのディレクトリに下位のディレクトリを作ってファイルを置く場合は、パターン（`/*`）を見直す必要がある。
- GitHub から導入した場合（プラグインがキャッシュのディレクトリに置かれる場合）にも同じように効くかは、デザインドキュメントの T8 で確かめる。
  - 追記（T8 の結果）: キャッシュのディレクトリから読まれる場合も、確認なしで読めた。
- 追記（T8 で分かったこと）: `allowed-tools` を持つスキルを Claude が自分で呼ぶと、スキルの実行そのものに承認を求められる（`claude -p` では拒否される）。対象は Claude が起動できる `ask`・`adr` で、人間がコマンドを入力した場合は求められない。`allowed-tools` を外すと、今度は補助ファイルを読むたびに確認が出るため、この決定は変えない。確認を省きたい利用者は、権限の設定で `Skill(sdd:ask)`・`Skill(sdd:adr)` を許可する。

## 検証方法（任意）
- `grep -rn '^allowed-tools:' plugins/` の結果が、`ask`・`adr`・`design`・`init` の 4 件で、どれも `Read(/${CLAUDE_SKILL_DIR}/*)` であること。
- 一時的な git リポジトリで、`--plugin-dir` を付けた `claude -p` から各スキルを実行し、補助ファイルの Read で許可を求められないこと。
