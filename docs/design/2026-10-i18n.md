# 多言語対応（出力言語の設定と英語の公開ファイル）

- Status: Approved
- 作成日: 2026-10-20
- 関連 ADR: docs/adr/0003-guide-as-single-source.md（Superseded にする予定）、docs/adr/0004-allow-reading-skill-files.md、docs/adr/0006-i18n.md（T1 で起票）

## 1. 背景と目的
- 今の sdd は、スキルの会話も、生成するデザインドキュメント・ADR・CLAUDE.md も日本語だけで、日本語を読めない利用者には使えない。
- リポジトリの README・guide・CHANGELOG・マニフェストも日本語だけである。コントリビューターにとっては英語のほうが広く読まれる。
- 成功の定義:
  - 利用者が、プラグインを有効にするとき（または `/config`）に `ja` か `en` を選べる。
  - 選んだ言語で、sdd のすべてのスキルとエージェントが会話し、ファイルを生成する。
  - GitHub でリポジトリを開いた人が、英語の README から導入と使い方を理解できる。

## 2. スコープ
- やること:
  - plugin.json の `userConfig` に `language`（`ja` / `en`、既定 `en`）を追加する。
  - 全スキル（ask・init・design・adr・ship）とエージェント（verifier）が、`${user_config.language}` に従って会話し、ファイルを生成する。
  - 補助ファイル（guide・各テンプレート・adr-0001・claude-md-template）を、英語（正本）と日本語訳の 2 つにする。
  - SKILL.md とエージェント定義の本文・description・argument-hint を英語にする。
  - README・CHANGELOG・guide・マニフェストの description を英語の正本にし、README と guide の日本語訳を置く。
  - CLAUDE.md の規約を、新しい方針に合わせて直す。
- やらないこと（Non-goals）:
  - ja・en 以外の言語。
  - プロジェクトごとの言語設定。言語は利用者ごとの設定に必ず従う。既存の文書の言語に合わせて自動で切り替えることもしない。
  - 既存のプロジェクトにある生成済みの文書の翻訳。
  - 開発用の文書（CLAUDE.md・docs/design・docs/adr）の英語版。これらは日本語のまま残す。
  - CHANGELOG の日本語訳。

## 3. 要件
- REQ-1: プラグインを有効にしたとき、または `/config` で、利用者が言語を `ja` / `en` から選べること。選ばなかったときは `en` になること。
- REQ-2: `/sdd:ask`・`/sdd:init`・`/sdd:design`・`/sdd:adr`・`/sdd:ship`・`sdd:verifier` が、設定した言語で会話（質問・案内・報告）すること。
- REQ-3: init・design・adr が生成するファイル（CLAUDE.md、デザインドキュメント、ADR）の見出しと本文が、設定した言語で書かれること。テンプレートは言語ごとのファイルを使うこと。
- REQ-4: ask は、設定した言語の guide を読んで案内すること。ja 版と en 版の guide は、判断基準の内容（表・手順・コマンド）が一致していること。
- REQ-5: 設定の値が `ja` 以外（未設定や想定外の値を含む）のときは、英語版のファイルを使い、英語で出力すること。
- REQ-6: README.md・CHANGELOG.md・guide.md・marketplace.json と plugin.json の description が英語で書かれていること。README.ja.md・guide.ja.md に日本語訳があり、README の先頭に相互のリンクがあること。
- REQ-7: 現在地の判定に使う記法が、どちらの言語のテンプレートでも同じであること（`- Status: Draft | Approved | Implemented`、`- [ ]` / `- [x]`）。
- 非機能要件:
  - 互換性: `userConfig` の `options` に必要な Claude Code v2.1.271 以上を README の前提に書く。
  - セキュリティ: 既存の方針（ADR 0003・0004）を保つ。スキルのディレクトリの外は読まない。`allowed-tools` は `Read(/${CLAUDE_SKILL_DIR}/*)` だけにする。
  - 検証: `claude plugin validate --strict .` が警告なしで通ること。

## 4. 設計
- 全体方針:
  - 設定は plugin.json の `userConfig.language` で持つ。指定内容は `{"type":"string","title":"Language","description":"...","options":["en","ja"],"default":"en"}`。値は、スキルとエージェントの本文の `${user_config.language}` に埋め込まれる。
  - 各 SKILL.md の本文の冒頭に、言語の指示を置く。英語の指示文で次の 2 点を書く。
    - 会話も生成するファイルも `${user_config.language}` で書く。`ja` なら日本語、それ以外は英語。
    - 補助ファイルは、`ja` なら `<名前>.ja.md` を、それ以外は `<名前>.md` を読む。
  - 補助ファイルの名前は「英語の正本 = `<名前>.md`、日本語訳 = `<名前>.ja.md`」にそろえる。同じディレクトリの直下に置くので、ADR 0004 の `Read(/${CLAUDE_SKILL_DIR}/*)` の範囲に収まる。
  - 判定に使うキーワード（`Status: Approved` など）と `- [ ]` は、どちらの言語でもそのまま使う（REQ-7）。
- ファイル構成（変更後）:
  - `plugins/sdd/skills/ask/`: `SKILL.md`（英語）、`guide.md`（英語・正本）、`guide.ja.md`
  - `plugins/sdd/skills/design/`・`adr/`: `SKILL.md`、`template.md`、`template.ja.md`
  - `plugins/sdd/skills/init/`: `SKILL.md`、`claude-md-template.md`・`.ja.md`、`adr-0001.md`・`.ja.md`
  - `plugins/sdd/skills/ship/SKILL.md`、`plugins/sdd/agents/verifier.md`: 英語。補助ファイルなし
  - ルート: `README.md`（英語）、`README.ja.md`、`CHANGELOG.md`（英語。0.1.0 の記載も英訳する）
- 検討した代替案と不採用の理由（ADR 0006 に記録する）:
  - Claude Code の `language` 設定に従う方法: プラグイン側の設定が要らない。しかし、生成ファイルの言語を決めて切り替える手段が無く、「インストール時に聞く」という要望にも合わない。
  - 補助ファイルを 1 つにして 2 言語を併記する方法: 読み込む量が倍になる。テンプレートの見出しをどちらにするかもあいまいになる。
  - 日本語を正本にして英語版を足す方法: GitHub で最初に表示されるのが日本語になり、コントリビューターに向けるという目的に合わない。

- [ ] T2: plugin.json に `userConfig.language` を追加し、`version` を 0.2.0 に上げ、description を英語にする。marketplace.json の description も英語にする。`--plugin-dir` で、試験用のスキルの本文に `${user_config.language}` が既定値 `en` で埋め込まれること、設定を変えると `ja` になることを確かめる。設定ファイルでの書き方も記録する（REQ-1, REQ-5）
- [ ] T3: ask を書き換える。今の guide.md を guide.ja.md に移し、英語の guide.md を作る。SKILL.md を英語にし、言語の指示を入れる（REQ-2, REQ-4, REQ-5）
- [ ] T4: design を書き換える。template.ja.md（今の内容）と英語の template.md を用意し、SKILL.md を英語にする（REQ-2, REQ-3, REQ-7）
- [ ] T5: adr を書き換える。内容は T4 と同じ（REQ-2, REQ-3, REQ-7）
- [ ] T6: init を書き換える。claude-md-template と adr-0001 の英語版・日本語版を用意し、SKILL.md を英語にする（REQ-2, REQ-3）
- [ ] T7: ship と verifier を英語にし、言語の指示を入れる（REQ-2）
- [ ] T8: README.md を英語にし、README.ja.md を作る。前提に v2.1.271 以上を書き、言語の設定と変更の方法（`/config`）、混在したときの注意を書く。CHANGELOG.md を英語にし、0.2.0 を追記する（REQ-6）
- [ ] T9: CLAUDE.md の規約「公開物はすべて日本語で書く」を直す。利用者向けの文書は英語が正本で日本語訳を併置すること、訳は同じ変更で更新すること、開発用の文書は日本語で書くことを定める（REQ-6）
- [ ] T10: 一時的な git リポジトリで、`--plugin-dir` と `claude -p` を使い、en（既定）と ja のそれぞれで ask・adr・init を実行する。出力とファイルの言語を確認する（REQ-1〜REQ-5, REQ-7）

## 6. テスト・検証方法
- 共通（タスクごと）: `claude plugin validate --strict .` が警告なしで通ること。
- REQ-1: `/config` に Language の行が出て、`en` と `ja` から選べること（手で確認する）。設定しないときは、T2 の試験で `en` になること。
- REQ-2・REQ-3・REQ-5: T10 で、en では英語、ja では日本語で応答し、生成ファイルの見出しが該当する言語のテンプレートと一致すること。
- REQ-4: `diff <(grep -c '^|' guide.md) <(grep -c '^|' guide.ja.md)` で表の行数が一致すること。見出し（`^#`）の数も同様に一致すること。
- REQ-6: 補助ファイルがすべて対になっていること。`plugins/sdd/skills/*/` の `*.md` のうち `SKILL.md` を除くものごとに、対応する `.ja.md` があることを ls で確認する。README の先頭に相互のリンクがあること。
- REQ-7: `grep -n 'Status: Draft | Approved | Implemented' plugins/sdd/skills/design/template*.md` が 2 件であること。
- セキュリティ: `` grep -rnE '\.\./|!`' plugins/ `` が 0 件であること。`grep -rn '^allowed-tools:' plugins/` が ask・adr・design・init の 4 件で、どれも `Read(/${CLAUDE_SKILL_DIR}/*)` であること。

## 7. 未決事項
- なし。T2 の確認で `${user_config.language}` が SKILL.md の本文に埋め込まれないと分かった場合は、実装を止めて設計を見直す。
- 既存の利用者が更新したときに、設定のダイアログが出るかどうかは T10 で確かめ、結果を README に反映する。出なければ、既定の `en` が使われる。
